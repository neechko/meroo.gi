  1. Arsitektur & Struktur Monorepo

  Proyek ini menggunakan pnpm workspaces + Turborepo (package.json, pnpm-workspace.yaml, turbo.json) dengan 3
  aplikasi utama dan 2 shared package:

  • Backend API (apps/api) — Go 1.22 (chi/v5, golang-jwt/v5)
      • Entry point di apps/api/cmd/server/main.go dan routing di apps/api/internal/router/router.go, siap deploy ke
      Vercel (apps/api/vercel.json).
      • Autentikasi & RBAC melalui apps/api/internal/middleware/rbac.go yang memverifikasi JWT Supabase lalu
      mengambil role (consumer, worker, admin) langsung dari tabel profiles.
  • Web Frontend (apps/web) — React 18, Vite, Tailwind CSS, React Router DOM v7 (apps/web/package.json)
      • Routing di apps/web/src/App.tsx mencakup katalog, detail layanan, keranjang (CartContext), tracking order,
      riwayat ulasan, profil, serta dashboard WorkerDashboard dan AdminDashboard.
      • Panduan & aturan web tersedia di apps/web/AGENTS.md (UI web berbahasa Inggris dengan tema dark glassmorphism).
  • Mobile App (apps/mobile) — Expo SDK ~58, React Native 0.88.1, React 19 (apps/mobile/package.json)
      • Navigasi utama berbasis tab/pager di apps/mobile/App.tsx (HomeScreen, CatalogScreen, OrdersScreen,
      WorkerScreen, AdminScreen, ProfileScreen) dengan dukungan Expo Updates & OAuth.
      • Klien Go API ada di apps/mobile/src/lib/goApi.ts.
  • Shared Packages (packages/shared, packages/supabase)
      • @meroogi/shared: konstanta merek & server Genshin (packages/shared/src/constants.ts), formatter rupiah/jam
      (packages/shared/src/formatters.ts), preset checklist harian/mingguan/bulanan
      (packages/shared/src/checklists.ts), klien REST Go API MerooApiClient (packages/shared/src/api.ts), dan token
      tema (packages/shared/src/theme.ts).
      • @meroogi/supabase: typed database schema (packages/supabase/src/database.ts).
  • Database (database/)
      • database/schema.sql dan database/migration.sql mendefinisikan tabel profiles, categories, services,
      service_tiers, orders, progress_updates, messages, reviews, beserta RLS policies dan trigger otomatis
      (handle_new_user, sync_worker_active_orders, set_order_deadline, update_worker_rating, set_review_service_id).

  2. Fitur Inti di Backend Go (apps/api)

  Berdasarkan apps/api/internal/router/router.go dan handler di apps/api/internal/handlers/api.go,
  apps/api/internal/handlers/auth.go, apps/api/internal/handlers/profile_progress.go, dan
  apps/api/internal/handlers/workers.go:

  1. Login via Username/Email: ResolveIdentifier menerjemahkan username ke email pada tabel profiles.
  2. Order & Struk: Pembatalan order (CancelOrder untuk status pending/paid) dan generator struk transaksi
  tekstual/JSON (apps/api/internal/receipt/generator.go).
  3. Vault Kredensial Akun Game: Password akun Genshin dienkripsi dengan AES-256-GCM
  (apps/api/internal/crypto/vault.go), dibatasi aksesnya hanya untuk admin/worker yang ditugaskan saat order masih
  aktif, serta mendukung alur permintaan & pengiriman kode verifikasi (HandleVerificationCode).
  4. Checklist & Progress Order: Checklist daily/weekly/monthly per order (ListChecklists, CreateChecklistItem,
  ToggleChecklistItem) dan update progres (CreateOrderProgress yang menjalankan insert ke progress_updates dan patch
  orders secara paralel dengan goroutine, serta EditOrderProgress).
  5. Smart Worker Priority Scheduler: apps/api/internal/priority/scheduler.go menilai dan mengurutkan worker
  (RankWorkersForTask) berdasarkan kelayakan (online, tidak cuti, belum penuh, senioritas mencukupi) dan bobot
  default: Fair Load 50%, Skill Match 30%, dan Rating 20%.
  6. Manajemen Keuangan & Admin: Pengaturan bagi hasil (finance_settings default 75% worker, 15% admin, 10% treasury
  studio) dan pencatatan alokasi per order (financial_allocations), manajemen akun/role/invite worker (InviteWorker,
  UpdateUserAccount), serta hapus layanan dan edit/hapus ulasan.

  3. Catatan Penting / Ketidaksesuaian yang Terlihat di Kode

  Beberapa hal yang perlu diperhatikan jika Anda ingin melanjutkan pengembangan:

  • Sinkronisasi Web vs Mobile ke Go API: apps/mobile sudah memanggil endpoint Go API melalui
  apps/mobile/src/lib/goApi.ts, sedangkan apps/web saat ini hanya berkomunikasi langsung dengan Supabase (belum
  memakai Go API /v1/* ataupun MerooApiClient dari @meroogi/shared).
  • Mismatch Action Kode Verifikasi (Mobile vs Go API): Di apps/mobile/src/lib/goApi.ts:97-106,
  requestVerificationCode mengirim action: 'request_code' dan submitVerificationCode mengirim action: 'submit_code',
  sedangkan HandleVerificationCode di Go API mengharapkan "request" atau "submit" (sama seperti yang dipakai di
  packages/shared/src/api.ts:39-44).
  • Skema SQL vs Tabel yang Dipakai Go API: Handler Go API mengakses tabel order_credentials, order_checklists,
  finance_settings, financial_allocations, dan worker_invites serta kolom profiles.username / profiles.contact_info /
  services.required_seniority, yang belum ada di database/schema.sql maupun packages/supabase/src/database.ts
  (kemungkinan sudah dibuat langsung di Supabase remote).
  • Tema Mobile (design.md vs sage.ts): apps/mobile/design.md mendokumentasikan desain dark glassmorphism ("Fontaine
  Abyss"), sementara kode aktif di apps/mobile/src/theme/sage.ts dan apps/mobile/App.tsx menggunakan palet SAGE
  bernuansa terang (soft sage-mist).
  • Keamanan Secret di Repo:
      • apps/api/internal/router/router.go:19-21 menggunakan fallback masterKey hardcoded ("meroogi-default-32byte-
      vault-key") jika ENCRYPTION_MASTER_KEY tidak diset tepat 32 byte.
      • plan.txt:61-62 menyimpan catatan Google Client ID dan Client Secret dalam plaintext.


  Kalau ada bagian spesifik yang ingin Anda kerjakan berikutnya (misalnya memperbaiki bug sinkronisasi, menyambungkan
  apps/web ke Go API, integrasi Midtrans, atau cek fitur mobile), beri tahu saja!
